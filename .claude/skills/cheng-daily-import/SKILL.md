# 承日常匯入 JSON

「承日常」是使用者自己的個人小助手 App（待辦、健康、帳單、寵物、食譜與想吃的店）。每個頁面都有「貼上匯入」：使用者把你整理好的 JSON 貼進去，App 會先檢查、請使用者核對，確認後才寫進 Google Sheet。你的工作是把照片或文字**準確**地變成那份 JSON。

## 先判斷是哪一種，再讀對應的格式檔

| 使用者給你的東西 | 讀這個檔 |
|---|---|
| 體脂計的測量結果截圖（體重、體脂率、肌肉量…） | `references/body.md` |
| 人的驗血報告（血糖、膽固醇、肝腎功能…） | `references/labs.md` |
| 寵物的驗血報告（IDEXX、ALT、BUN、CREA…，有寵物名字） | `references/pet-labs.md` |
| 水費、電費、瓦斯帳單（含帳單附註的歷史用量） | `references/utilities.md` |
| 店名、餐廳小吃、IG／YouTube 美食貼文 | `references/places.md` |
| 食譜網頁、截圖或文字 | `references/recipes.md` |

只讀這次用到的那一個檔就好。一次丟了好幾種就分開處理，每種各輸出一個 JSON 區塊並標明是哪一種。

## 六種共通的規則（為什麼：資料會直接進使用者的紀錄，錯了很難發現）

- **只輸出 JSON 區塊**（```json），不要在 JSON 裡加註解。JSON 外面可以簡短說明依據、不確定的地方、需要使用者確認的事。
- **看不清楚、不確定的數字或欄位，不要猜**：列出來問使用者，或在 JSON 裡省略該欄位。報告上沒有的欄位也省略，不要補預設值、不要用自己的常識填。
- **照原文，不換算單位、不改數值**。日期一律西元 `yyyy-MM-dd`（民國年要換成西元，例如 115 年 = 2026 年）。照片上沒有日期就**先問使用者**（問完再給 JSON），不要用今天的日期假裝；他說「今天」才填今天。
- **個人資料不要抄進任何地方**：帳單與報告上的姓名、地址、電話、電號、水號、帳號、身分證字號、客戶編號等都只用來讀金額、日期和數值，不要放進 JSON、備註或你的回覆。
- **使用者的核對是最後一道關**：匯入只會把內容填進表單或先給確認視窗，所以交付時簡短列出你的推測與沒把握的地方，讓他核對得快。
- 在 Claude app 的對話裡你**看不到 App 裡已有的資料**（已經記過的標籤、項目名稱）。需要「跟以前一致」的地方，優先沿用各格式檔裡列的標準寫法；沒有把握就問使用者，或請他貼一份目前的清單。

## 回覆的樣子

1. 一個 JSON 區塊（或每種一個）。
2. 一張很短的核對重點：日期是怎麼來的、哪些欄位是推測、哪些看不清楚被省略、有哪些沒放進去。
3. 提醒貼上的位置（各格式檔最後一行寫了是哪一頁、哪個按鈕）。
