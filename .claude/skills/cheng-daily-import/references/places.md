# 想吃的店（飲食頁 → 想吃的店 → ＋ 新增店家 →「批次貼上匯入」）

使用者看影片、IG 發現餐廳小吃，先只記**店名**，有空再請你補「第二層」資料。可以一次很多家（上限 200）。匯入是**依店名比對已有的店、只補空白欄位**（不會蓋掉使用者自己寫的內容；使用者勾「覆蓋已有內容」才覆蓋），找不到就新增。

```json
{ "items": [ { "name": "阿財滷肉飯", "country": "台灣", "city": "台北市", "area": "大安區", "tags": ["小吃", "滷肉飯"], "dishes": "滷肉飯、燙青菜", "mapUrl": "https://maps.app.goo.gl/example", "source": "https://www.instagram.com/p/example", "note": "建議早餐去，中午要排隊" } ] }
```

## 欄位
- `name`：**唯一必填**（≤100 字）。
- 地區三層：`country`（台灣、日本…）→ `city`（台灣用完整縣市名：台北市、新北市、台中市、彰化縣…；國外用城市：大阪）→ `area`（行政區或商圈：大安區、秀水鄉、難波…）。優先沿用使用者之前的寫法。
- `tags`：字串陣列，類型（小吃、早午餐、甜點、咖啡、火鍋、拉麵、義大利麵、越南菜…）與場合（約會、聚餐…）；每個 ≤20 字、最多 10 個。優先沿用已有的標籤（在 Claude app 看不到，就問使用者要沿用哪些，或沿用上面的常見寫法）。
- `dishes`：特色餐點，簡短（≤300 字）。
- `mapUrl`：**只放確實查到的 Google 地圖店家連結**（`https://www.google.com/maps/place/…` 或 `https://maps.app.goo.gl/…`）。**不要放搜尋連結、不要自己組網址、不要放 Apple 地圖或其他地圖**；查不到就省略（使用者會自己在 Google 地圖按「分享」貼進去）。
- `source`：使用者給的 IG／YouTube 連結，照抄；只收 `http(s)://`。
- `note`：建議時段（建議早餐去、午餐要排隊）、公休日（寫「網路資料，出門前確認」）、只收現金、招牌、附近捷運站等，≤1000 字。
- **不記營業時間**（會變動、容易過期）。

## 只靠店名補資料時（誠實是第一優先）
1. **用網路搜尋查證**（可以用的話）。同名的店很多，只靠店名會猜錯：多個來源指向同一家、地址一致才有把握。
2. **沒把握的欄位省略**，不要編。區域不確定就只給 `country`，並在回覆列出來問使用者。
3. 回覆裡用一張小表列出每家的**把握程度**（高／中），中等的說明哪裡不確定（例如「這個店名不只一家」）。
4. 使用者有給截圖、貼文說明或連結時，以那個為準，把握會高很多，也能把連結放進 `source`。
5. 查不到確切 Google 地圖連結時，**明講沒放**，不要用搜尋連結湊。

貼到：飲食頁 → 想吃的店 → ＋ 新增店家 → 彈窗最上面「批次貼上匯入」→「檢查並匯入」（貼上後按底下的「新增」也一樣）→ 確認「N 家新增、M 家補充」。
